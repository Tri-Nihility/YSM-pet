## 3. 核心技术约定（**最容易搞错，改代码前必读**）

### 3.1 坐标系
**模型空间**（YSM 原生，右手系，1 方块 ≈ 1 米）：
```
+X = 角色右侧      -X = 角色左侧
+Y = 上
-Z = 角色正前方    +Z = 角色正后方
```
实测判据：LeftArm 质心 x = -0.244 / RightArm +0.244；Eyes/Eyelid 质心 z ≈ -0.21；脚尖 z ≈ -0.20。

**pybullet 空间**（Z-up）转换矩阵 `P`（`det = +1`，纯旋转，保手性）：
```
pb = P @ model ,   P = [[0,0,-1],
                        [-1,0,0],
                        [ 0,1,0]]
即 px = -mz（前）   py = -mx（右→-Y）   pz = my（上）
```
重力写 `(0, 0, -9.81)`（pybullet 的 -Z）。

### 3.2 关节角符号（**全项目最大的坑**）
- 约定：关节角 `q`（度）= 绕 `+X_model` 轴的**右手正向旋转**；**q > 0 = 肢体向前（-Z）摆**。
- 驱动 YSM 骨骼时 **`rotation.x = -q`**（上游 `RotationValue` 对 X/Y 取负，Z 不取负）。
- URDF 里关节轴在 pb 空间是 `axis=(0,-1,0)`。
- 前端 three.js：`b.rotation.set(-(angles[i]) * PI/180, 0, 0)` 且 `rotation.order = "ZYX"`。
- 上游 FK 权威公式：`M = M_parent · T(pivot) · Rz·Ry·Rx · S · T(-pivot)`，其中 `R = Rz(rz)·Ry(-ry)·Rx(-rx)`。

改这三处符号任意一个，模型就会「膝盖反着弯 / 手往身体里插」。改完务必跑 `scripts/_smoke_urdf.py`（应输出 err = 0.00000）和 `scripts/step4_build_skeleton.py` 看 `joint_range.png`。

### 3.3 YSM 是「烘焙网格」，不是标准蒙皮
`.ysm` 存的是**模型空间烘焙顶点 + UV**，rest 时骨骼矩阵 = 单位阵，**没有 inverse-bind matrix**。动画值直接叠加。导出 glTF 时人为造 IBM = `T(-pivot)`，顶点权重 = 本骨骼 1.0（刚性蒙皮）。

### 3.4 表情 = 显隐，不是形变
YSM 的表情是**并列骨骼 + `scale=(0,0,0)` 隐藏**。所以接口设计为「槽位 + 互斥选项」：`configs/expressions.yaml` 里 5 个槽位（face/brow/eyes/mouth/blink）共 25 个选项，每个选项是一串骨骼名；选中项正常显示，同槽位其他项全部 `scale=0`。训练时 `enabled: false`（否则观测维度会变）。

### 3.5 质量必须人工标定，**不能按体积自动分配**
YSM 的头发/裙摆是**空心薄壳**，AABB 体积累加会把头部吹到 **39%**（实测 240 根骨骼 1.15 方块³），头重脚轻根本学不会站立。
现在走 `configs/joints9.yaml → mass.override`（Winter 体段占比表 × 51.8 kg）：
```
pelvis 10.0 | torso 15.5 | head 4.3
upperArmL/R 1.5 | foreArmL/R 1.1 | thighL/R 5.2 | shinL/R 3.2
```
`auto_from_volume: true` 是保留的对照模式（带 `max_segment_share: 0.34` 限幅）。若换模型，**必须重标 override**，否则 `_masses()` 会直接抛 `KeyError` 告诉你缺哪段。

### 3.6 ⛔ 禁用自带动画
`configs/joints9.yaml` 里 `use_native_animation: false` 是**硬开关**，`Skeleton9._check()` 会强制校验。所有姿态只能来自 9 个关节角 + 表情显隐。`src/ysm/animation.py` 只作为格式参考保留，训练/渲染管线不加载它。

## 6. 当前失败诊断与下一步建议（**接手先看这里**）

### 6.1 实测数据（iter 133 的 `stand_best.pt`，5 回合确定性回放）
```
ep00 ret=326.63 len= 46/180 h=0.89 tilt=43.6° FALLEN
ep01 ret=375.80 len= 57/180 h=0.90 tilt=45.4° FALLEN
ep02 ret=289.36 len= 43/180 h=0.91 tilt=34.0° FALLEN
ep03 ret= 20.58 len=  6/180 h=0.91 tilt=23.7° FALLEN
ep04 ret=600.70 len= 86/180 h=0.94 tilt=45.3° FALLEN
→ survival_rate 0.0 | mean_len 47.6/180 | mean_tilt 38.4° | mean_h 0.912  → PASS=False
```
对比基线：零动作 50.6 步、随机动作 13.2 步。所以 **iter 133 的策略在长度上还没明显超过「不动」**，只是单步回报更高（学会了保持高度）。

### 6.2 根因（按可能性排序）

**① 结构性缺陷：9 个关节全部只有矢状面（sagittal）一个自由度**
所有 9 个关节的轴都是模型 `+X`，只能做前后摆动。**没有任何侧向（roll）自由度**，也没有脚踝关节。这意味着：
- 一旦出现侧向倾斜，**物理上无法纠正**，只能等倒；
- 没有踝策略，压力中心（COP）无法在支撑面内平移，只能靠髋/膝整体晃动找平衡 —— 这在真实生物力学里就是「学不会站立」。

**② 倒地判据过严**：`max_tilt_deg: 45` + `target_height_ratio: 0.92` 两个条件 **OR**。实测 4/5 回合是撞倾角线倒的（43.6 / 45.4 / 45.3），高度其实一直达标（0.89~0.94）。agent 学会的是「保持高度但身体侧倾」，一倾到 45° 就被判死，梯度信号很差。

**③ 无用关节在稀释探索**：站立阶段肘（0/1）和脖子（8）对平衡毫无贡献，但占了 3/9 的动作维度，白白放大探索方差。

**④ 训练量不足**：250 迭代 × 4096 步 ≈ 100 万步，对 9 维连续控制偏少，且被中途打断。

### 6.3 建议的下一步（**按顺序做，做完一条就评估一次**）

1. **给髋/肩加外展轴（frontal, Z 轴）** —— 关节数仍是 9 个，只是 `leftHip/rightHip` 从 1 DOF 变 2 DOF（矢状 + 额状），动作维度 9 → 11。这是解决①的正解，也最符合「人怎么站稳」。需要同步改 `bind.py` 的 `build_urdf()`（加第二个 revolute joint + 虚拟 link）和 `joint_to_anim()`（两个角合成一个四元数）。
   > ⚠️ 这会改变动作维度，需要用户确认「9 个关节」是否允许内部 2 自由度。**先问再做。**

2. **课程化倾角阈值** —— `max_tilt_deg` 从 45° 起步，每个 50 迭代收紧 5°，最终 20°。改 `phys.yaml` 加 `tilt_schedule`，`_fallen()` 按当前迭代取值。风险低、见效快。

3. **屏蔽无用关节** —— stand 阶段给 elbow×2 + neck 加 action mask（输出恒为 default），动作维度降到 6。改 `joints9.yaml` 加 `stage_mask: {stand: [...]}`，环境里做。

4. **奖励整形** —— `upright` 2.5 → 4.5；`com_over_feet` 改用真实支撑多边形（现在是「骨盆到脚中心的距离」高斯，没考虑支撑面形状和朝向）。

5. **关掉横向扰动** —— `domain_randomization.initial_push` 现在对 x/y 都加 ±0.15 m/s，横向分量在①没修好前是纯噪声。改成只推 x。

6. **跑满训练** —— 上面改完后 `stand` 至少 400 迭代 × 4096 步（约 2 小时），或 800 迭代 × 2048 步。

7. 站立过线后再做 `walk`：热启动 `stand_final.pt`，奖励切到 `forward_vel + contact_alternation`，并记得 `curriculum.walk.warmstart_from: stand` 已配好。

### 6.4 行走阶段可以预见的坑
- 行走需要**摆动腿离地**，但脚掌是 `fixed_attachment`，没有踝关节 → 抬脚全靠屈膝屈髋，容易拖地。可能得引入第 10 个关节（踝），同样要用户确认。
- `contact_alternation` 奖励依赖 `foot_contacts` 从 `[1,1]` 变成单脚，判据写得比较窄（`contacts.sum()==1 and last.sum()==1 and 不相等`），后续大概率要放宽。

## 7. 已知边界 / 不要踩

| 事项 | 说明 |
|---|---|
| `p.changeDynamics` 对 pelvis | pelvis 是根 link，pybullet 索引是 **-1**，不是 0。代码里已 `link_of[root.segment] = -1`。 |
| `setJointMotorControlArray` | **不支持 `maxVelocity` 关键字**，传了直接 `TypeError`。 |
| `getLinkState()` | `[0]` 是**质心**，`[4]` 才是 URDF frame 原点，`[5]` 是惯性系四元数。对齐 FK 必须用 `[4]/[5]`，用 `[0]` 会算出 0.16~0.36 的假误差。 |
| URDF 关节顺序 | pybullet 按 **URDF 树序**返回（leftShoulder→leftElbow→rightShoulder…），和配置顺序（肘/膝/肩/髋/脖）**不一致**。代码用 `jidx` 字典映射，别假设顺序。 |
| GLB 的 `JOINTS_0` | 骨骼数 257 > 255，必须用 `uint16`（componentType 5123），用 uint8 会 `OverflowError`。 |
| GLB 结构 | 每根带网格的骨骼 = 一个 mesh + 一个 node，node 上有 `extras.bone`，GUI 靠它做表情显隐。**不要合并 mesh**，合并后表情接口就废了。 |
| torch | 只装 CPU 版。`ppo.py` 里 `torch.set_num_threads(min(4, cpu_count))`。 |
| `outputs/logs/stand_train.csv` | 当前是 **0 字节**（被中止的那次运行用的是 flush 修复前的代码）。下次训练会正常写。 |
| 临时文件 | `临时文件（记得整理掉/` 里有原始 `.ysm` 和上游源码快捷方式，**交接时别删**，解析器回归测试还要用。 |
