# 05 模型格式调研（实测结论）

> 2026-10-04，第一步「引擎 + 场景 + 模型 + 渲染」完成过程中验证的所有格式事实。
> 素材：`临时文件（记得整理掉/苦力怕狐`（明文模型包）、`亚托莉（目标模型）.ysm`、`爱恩.伊瑞丝.卡列尼娜.ysm`（加密）。

## 1. YSM 模型的两种形态

| 形态 | 结构 | 可解析性 |
|---|---|---|
| **明文文件夹包**（苦力怕狐） | `ysm.json` 清单 + `models/*.json` + `animations/*.json` + `textures/` + `controller/` + `functions/`(molang) | ✅ 完整可解析 |
| **.ysm 打包文件**（亚托莉、爱恩） | 文本头 `YSGP` + 分段（Metadata/Tips/Export/Source SHA-256/Codec Version）+ **加密数据区** | ⛔ `<crypto> 3` 加密，无法直接读出模型 |

.ysm 头部能读到的信息：模型名、作者、SHA-256 清单、`<format> 15` `<crypto> 3`。
**结论：训练与导出管线基于明文包格式开发；亚托莉需要先拿到明文/解密版本。**

## 3. 几何/骨骼格式（models/main.json，Bedrock geometry 1.12.0）

```
minecraft:geometry[0].bones[]  每根骨骼:
  name, parent(可为空), pivot[3], rotation[3](度,可选), cubes[](可选)
每个 cube:
  origin[3], size[3], uv, pivot[3]+rotation[3](可选, cube 自转), mirror
```

苦力怕狐 main.json 实测：**203 骨骼 / 112 含几何 / 477 cube**。

### 坐标系与 FK 语义（★ 已用上游源码逐行确认，2026-10-04）

上游依据：`YSM-Liaison/mod/common/.../resource/YSMFolderDeserializer.java` L505-645、
`geckolib3/geo/NativeModelRenderer.java` `calculateBoneMatrix`。

- 单位：JSON 里 `origin/size/pivot` 都是**像素**（1 block = 16）；渲染时 /16 变方块单位。
- **渲染空间相对 JSON 空间 X 取反**（镜像）：
  - `bone.pivot -> (-pivot[0], pivot[1], pivot[2])`（L509），再 `*0.0625`（= /16）
  - `cube: cx = -origin[0] - size[0] - inflate`（L531）
  - 即 `v_render = (-x, y, z) / 16`
- **骨骼矩阵**（bind pose）：`M = M_parent · T(p) · R · T(-p)`，p = 该骨骼 pivot 的渲染坐标
  - `R = Rz(rz) · Ry(-ry) · Rx(-rx)` —— 即 scipy 外旋 `"XYZ"`，参数 `[-rx, -ry, rz]`（度）
  - 全部 rotation=0 时 `M = I`（模型处于 T-pose），pivot 绝对坐标语义因此自然成立
- **cube 自转烘焙**（L542-546）：`T(a)·Rz(rz)·Ry(-ry)·Rx(-rx)·T(-a)`，`a = (-cpvt[0], cpvt[1], cpvt[2]) / 16`
- `inflate`：几何外扩（bone 级可作 cube 级缺省），六个方向各 +inflate
- 渲染空间(Y 上) -> pybullet(Z 上)：`(x,y,z) -> (x,z,y)`，旋转矩阵 `P·R·Pᵀ`（P 自身对称）
- **pybullet 相机 yaw 实测**（`computeViewMatrixFromYawPitchRoll`，`upAxisIndex=2`）：
  `yaw=0 → eye(0,-d,0)`（正面）、`90 → eye(d,0,0)`（角色左侧）、`180 → 背面`、`270 → eye(-d,0,0)`
- ⚠️ OpenBLAS 多线程在内存紧张时会 `Memory allocation still failed` 直接杀进程 ——
  必须**在 import numpy 之前**设 `OPENBLAS_NUM_THREADS=1` / `OMP_NUM_THREADS=1`（geometry.py 已内置）

### 显隐不是布尔开关，而是 5 种机制

1. **`scale = 0` 作为隐藏**（最常用）。`pre_parallel*` 系列"前置并行动画"先跑一遍把状态归零：
   - `Background1`（幕布背景）→ `pre_parallel4` scale=0，只在 `gui` 动画里 scale=1 → **仅 GUI 预览显示**
   - `Mask`（狐狸面具，55 cube）→ `pre_parallel1` scale=0，`head:default` scale=1 → 默认戴上
   - `MooncakleH`（月饼头饰）→ `pre_parallel0` scale=0 → 默认隐藏
   - `FoxEye` → `pre_parallel3` scale=0（8 帧）→ 狐狸眼睛条件显示
2. **同一部位两套几何，按状态二选一**：
   `关兜帽` 动画把 `hat` scale=0；`开兜帽` 把 `BaseHair`/`LongRightHair`/`LongLeftHair` scale=0。
   → 兜帽戴上时头发隐藏，头发露出时兜帽隐藏。
3. **上下文切换整套骨骼子集**（不同动画文件只驱动一小撮）：
   `fp.arm` 4 根（第一人称手臂）、`vehicle/horse` 12、`vehicle/mule` 11、`arrow` 12、`carryon` 21；
   main 里还有 `ride`/`ride_pig`/`boat`/`sleep`/`swim`/`sneaking`/`ladder_up`/`climb`/
   `vehicle$man_of_many_planes:scarlet_biplane` 等按玩家状态切换。
4. **`FOX` 骨骼 cubes=0**：狐狸本体不在 FOX 下，而分散在 `BM/BL/BR/LM/LF/RF/RM/LB/RB...`，
   FOX 只是挂点。所以"狐狸什么时候出现"要看这些骨骼的显隐，而不是 FOX 本身。
5. **表情骨骼独立于身体运动**：`Expression_1..7`、`Left/RightEyelid(_Base/_StarEye)`、
   `EyeBrow`、`Mouth(_chill/_smile/_smile2/_surprise)`、`weixiao(微笑)`、`jingya`。
   `sleep` 动画把 `Left/RightEyelid` scale=0（闭眼）。这些**不属于骨架运动**。

### 其他实测到的动画机制（做训练前必须知道）

- 关键帧**数值可以是 molang 字符串**：`Head.rotation[0] = "ysm.food_level<=6?25:0"`（饥饿度低就低头）
  → 静态解析拿不到数值，需要运行时求值或直接丢弃该帧。
- 插值有 **`lerp_mode: "catmullrom"`**（还有 pre/post 键），不是线性。
- **`scale` 通道真实存在且常 ≠ 1**：`ysmGlowTnt_Right_bone` scale=[3.33, 3.11, 3.175]，
  非均匀缩放。FK 必须支持 scale，否则该骨骼尺寸错。
- 9 个动画文件合计通道：rotation 1969 / position 797 / **scale 322**。
- main.animation.json 实际驱动 **186 根骨骼**（此前估计 23–28 是错的，那只数了少数几段）。
- `Body` 骨骼 0 段动画引用 → 纯静态跟随。

## 4. 动画格式（animations/main.animation.json，Bedrock animation 1.8.0）

```
animations.<动作名>: { loop: true|false|"hold_on_last_frame",
                      animation_length: 秒,
                      timeline: {...}(事件),
                      bones: { 骨名: { rotation|position|scale:
                                  { "0.0417": [x,y,z], ... } } } }
```

实测（walk）：
- 时间键是**秒**（字符串），帧间隔 0.0417s ≈ **24 fps**；walk 长 1s、run 长 0.6667s
- `rotation` 单位**度**，数值合理（腿部 ±27° 摆动）
- 主动画文件含 **66 段动画**（idle/walk/run/jump/fly/death/gui/sit/boat/sleep/swim/climb…）
- main.animation.json 驱动 **186 根骨骼**（详见 §3b —— 其中大量是表情/毛发/尾巴/衣摆，
  真正的"身体运动"核心仍是那一小撮）

## 5. 渲染管线（scripts/step1_load_and_render.py）

- 引擎：pybullet DIRECT + `getCameraImage`（本机**可正常软件渲染**，中心像素验证过）
- ⛔ `createVisualShapeArray` 会**段错误**（segfault）→ 必须**逐 cube 建 body**（466 个 body 可行）
- 每个 cube：`createVisualShape(GEOM_BOX) + createMultiBody(baseMass=0)`
- 模型自动归一化：bbox 居中 + 缩放到 1.8 m（与模型单位解耦）
- 全模型 466 cube 加载 + 渲染 4 视角约 1 分钟；核心 67 cube 几秒

## 5b. 贴图渲染（scripts/step1b_render_textured.py，自写软光栅）

pybullet 的 `GEOM_BOX` **不支持自定义 UV**，而 Bedrock 用 box-UV 布局 → 贴图必须自己光栅化：

- **box-UV 展开规则**（cube size=(w,h,d)，uv 原点 (u0,v0)）：
  `top(u0+d, v0, w×d) · bottom(u0+d+w, v0, w×d) · west(u0, v0+d, d×h) · north(u0+d, v0+d, w×h) · east(u0+d+w, v0+d, d×h) · south(u0+d+w+d, v0+d, w×h)`
- 贴图 `skin.png` 512×512 RGBA，**90.9% 透明**（稀疏 UV 排布，正常）；渲染需 alpha 测试（a≥100）
- 相机矩阵仍由 pybullet 提供：`computeViewMatrixFromYawPitchRoll / computeProjectionMatrixFOV`
  返回**列主序** 16 元列表，`np.array(m).reshape(4,4).T` 得行主序；验证手段：投影 target 应得 NDC≈(0,0)
- 光栅化：numpy 重心坐标 + z-buffer + 最近邻采样 + Lambert 光照（0.55+0.45·max(n·L,0)）
- per-face UV（dict 格式 `"uv": {"north": {"uv":[..], "uv_size":[..]}}`）与 box-UV（list 格式）两种都要支持；`mirror` 翻转 U
- 性能：core 402 面 <1s；full 2796 面 10s
- 效果：**core 模式贴图正确**（卫衣/袖口/鞋底花纹可辨）；full 模式装饰件漂移 = FK 遗留问题，与贴图无关

## 6. 对训练管线的直接推论

1. 骨架定义不再是"通用人形假设"，但也**不能直接用"动画驱动的 186 根"**——
   那里面混着表情、毛发尾巴、衣摆、显隐开关件和挂点。
   逐根分类见 **`outputs/bone_roles.csv`**（由 `scripts/step1c_bone_roles.py` 生成），分布：

   | 分类 | 数量 | 说明 |
   |---|---|---|
   | 挂点/组织（无几何） | 91 | `Root/MRoot/*Locator/molang*` |
   | 普通 | 30 | 中间层级、狐狸身体部件 |
   | **表情** | 28 | `Eyelid/EyePublic/Eyebrow/Mouth_*/Expression_*`，独立于身体运动 |
   | 毛发衣摆 | 19 | `LongHair*/Tail*/Clothe*/Dress/hat` |
   | **核心运动** | **18** | 17 根被动画驱动（`Body` 例外，静态跟随） |
   | 静态装饰 | 11 | 从未被动画驱动 |
   | 特效件 | 5 | `Background1/curtain/white_curtain/MooncakleH*` |

   另有 **20 根骨骼会被 `scale=0` 隐藏**（兜帽/头发二选一、闭眼、面具、月饼头饰、
   幕布背景、手部挂点…），逐根列在 CSV 的 `hidden_by_scale0` 列。

   → 训练目标 = **身体运动核心 18 根**，其余作为"结果"由 FK 派生。
   `configs/skeleton.yaml` 必须从模型自动生成，不能手写。
2. **FK 必须支持 `scale` 通道**（既有显隐用途，也有非均匀缩放如 `[3.33,3.11,3.175]`）。
3. **molang 关键帧**（`"ysm.food_level<=6?25:0"`）静态解析拿不到 → 训练集构建时要跳过
   含 molang 数值的帧，或引入一个极简 molang 求值器。
   → **2026-10-05：求值器已实现**，见 `10-桌宠项目.md` §15.4。模块 `src/ysm/molang.py`
   （词法 + 递归下降，支持三元/逻辑/比较/算术/一元/`math.*`/`ID = expr` 赋值/`;` 多语句，
   未知变量按 0），`src/ysm/animation.py` 的 `_vec()` 已接上；**含表达式的通道不走数值缓存**
   （否则运行时值会被冻成解析那一刻的值 —— 慧慧的 `!v.roaming.p` 曾因此把整个身体隐藏，
   见 `10-桌宠项目.md` §15.2 第 3 条）。
4. 插值要支持 `catmullrom`，不能只做线性。
5. 动画数据可直接反解为训练样本：每段动画 → 时间键采样 → 每帧各骨骼欧拉角(度) → 6D 表征。
6. 24 fps 与文档里假设的 30 fps 不同，`configs/default.yaml` 需改为 24。
7. **一个模型 = 多套状态**（正常/骑乘/睡觉/游泳/船/攀爬/载具/第一人称），
   训练样本要按状态分桶，不能混在一起当成一条序列。
   → **状态机的完整规格见 `06-上游状态机与渲染机制.md`**（控制器管线 17 层、
   main 层 19 个位移状态的优先级表、`parallel` 显隐机制、`ctrl.*` molang API）。
   配套产出：`outputs/bone_roles.csv`（骨骼角色）、`outputs/clip_states.csv`（133 段动画归类）。

## 现代二进制格式（format 16~64）：2026-10-05 已支持

本文档前面调研的是 **legacy 形态（format ≤ 15）**。新版 `.ysm`（上游 2.6.x，写端只产出
format ≥ 26）用的是**完全不同的顶层布局**，此前 `src/ysm/ysmbin.py` 直接
`raise NotImplementedError("modern format N 未移植")`，所以导入芙宁娜、斯卡蒂、铃兰这类
新皮肤会失败。

- 规格来源：本机 mod jar `openysm-fabric-2.6.5.9` 经 CFR 反编译得到的
  `YSMBinaryDeserializer` 读端源码（**不是**字节码推断），逐字段规格见
  **`12-YSM现代二进制格式读取规格.md`**（含版本分派表、顶层顺序、每个子结构、不确定项）。
- legacy vs modern 顶层差别：legacy 有开头 skip 块 + 结尾 3 张 hash 回填表；modern
  **没有回填表**（hash 内联在条目头部）、段顺序重排、多出 sounds/functions/languages
  与一等公民子实体（vehicles/projectiles 自带动画+控制器+贴图+几何）。
- 贴图象素格式也不一样：legacy 内嵌的是**裸 RGBA**（`w*h*4` 字节，`image_format=-1`），
  modern 内嵌的是**压缩图**（实测 PNG 与 WebP 都有，不透明地按文件头嗅探最稳）。
- 版本分界速查：`<4` legacyV1（仍未移植）、`≤15` legacyV15、`≥16` modern；
  子结构关键点 `>4`、`>9`、`≥15`、`>15`、`≥24`(footer unk_int2)、`≤26`/`>26`、`≥32`。
- 实测：`data/cache` 与 `data/decrypted` 下 16 个模型（format 4/9/15/26/28/32）全部解析且
  **尾部残留 = 0**（读到 footer 最后一字节零错位），`.ysm` 导入 + 冒烟渲染端到端通过。

### 模型文件的组织结构：人本体 / 特效 / 游戏内 UI 是按**根骨骼**分包的（★ 实测）

一个 `.ysm` / `.bin` 里的骨骼树不是「一个人」，而是**一个人 + 一堆按需显示的部件**，
它们挂在**不同的根骨骼**下。以 `慧慧1.2版本.ysm`（骨骼 968 / 面 24098）为例：

| 根骨骼 | 面 | 内容 |
| --- | ---: | --- |
| `girl` | 13932 (57.8%) | **人物本体**（含 `Head`） |
| `texiao` | 5642 (23.4%) | 特效（含 26 单位外的刀光 / 法阵） |
| `DAZ` | 2016 (8.4%) | 平面立绘（z 跨度 0.06，纯平片） |
| `MZ2` | 1926 (8.0%) | 部件 |
| `tx` | 420 (1.7%) | 部件 |
| `bone358` | 96 | 正贴人物中心的一块大面（8.67×8.47×2.56 单位） |
| `bone480` | 66 | 部件 |

- **人本体只占 57.8% 的面，其余 42% 是特效 / 立绘 / 游戏内 UI**。顶点跨度最大的
  12 根骨骼全是特效（`ysmGlow_dg1_a89..a94` 跨度 11.31×8.49×11.31、中心 z=−26.31；
  `D9/D10/D11` 8×0×8 在 z=−26.31；`ysmGlow_pd54/55` 8×0×8 在 (4, 2.19, 4)）。
- 其他模型的额外根**直接暴露了它们的用途**：斯卡蒂 / 铃兰里有
  `MUI`（游戏内面板）/ `BeiJing`（背景板）/ `MZhuanPan`（转盘）/ `MTouzi`（骰子）；
  苏沐星的 `Gui` 只有 **10 个面**却是一整块背景板（占 19% 画幅）。
- 作者靠自带的 **`pre_parallel*` 常驻层**在静止状态用 `scale=[0,0,0]` 关掉这些部件：
  慧慧这一层里 `scale=[0,0,0]` 的骨骼 58+ 根，整层 **`vis=False` 的面 = 11588/24098（48%）**。
  注意这一层同时也会**改人物本体的可见性**（慧慧里有 139 根骨骼 / 1422 面属 `girl`；
  斯卡蒂 805/1005 根本体骨骼都被它隐藏）→ **不能把它当成「部件清单」**，
  直接照它裁会切出残片。
- 对消费方的结论（桌宠「清晰模式」的判据）：**「包含 `Head` 的根子树」= 人本体**，
  其余根子树 = 部件；照这个裁，干净且可测（跨 6 个模型实测：干净的模型 IoU 1.000
  无误伤，脏的模型 IoU 0.156~0.763）。细节与实现在 `docs/10-桌宠项目.md` §16。
