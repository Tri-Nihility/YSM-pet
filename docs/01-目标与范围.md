# 01 目标与范围

## 一句话目标

输入一个条件（动作类别 / 控制信号 / 参考轨迹），输出**一串骨架姿态序列**，
经导出后能作为 YSM 模型的动画播放。

## 关键约束：YSM 的骨骼不统一

这是本项目最重要的事实，决定了整体架构：

- Minecraft 原版玩家模型骨骼是固定的（head / body / 双臂 / 双腿）
- **YSM 自定义模型的骨骼由模型作者定义**，数量、命名、层级、朝向各不相同
- 所以不存在一个"通用 YSM 骨架"，训练与导出必须绑定到**具体某个模型**

### 两条技术路线

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 绑定到单一模型** | 直接用某个 YSM 模型的骨骼训练 | 无需重定向，导出无损 | 换模型要重训；几乎没有现成数据 |
| **B. 通用骨架 + 骨骼映射（推荐）** | 用通用人形骨架训练，导出时重定向到目标 YSM 骨骼 | 可用现成动捕数据集；换模型只需换映射表 | 需维护骨骼映射；重定向可能失真 |

**推荐 B**。理由：动捕数据（AMASS 等）基于 SMPL 类骨架，数据量大且免费；
换 YSM 模型时只改 `configs/skeleton_map.yaml`，不必重训。

## 范围界定

### 本期做

- 单一人形骨架（类 SMPL / Mixamo 量级，约 20–25 个关节）
- 周期性 locomotion：idle / walk / run / jump（先做这四类）
- 输出定长序列（先 60–120 帧 @ 30fps）
- CPU 可训的小模型

### 本期不做

- 多人交互、物体交互
- 手指 / 面部精细动画（YSM 模型差异过大，性价比低）
- 非人形骨架（四足、机械）
- 实时推理部署（先离线生成）

## 待确认清单

> 以下问题需要你拍板，或让我按推荐项执行。

| # | 问题 | 推荐默认值 |
|---|---|---|
| 1 | 骨骼拓扑 | 通用人形 22 关节（SMPL 子集），配 YSM 映射表 |
| 2 | 数据来源 | AMASS / HumanML3D 子集；若你有现成 YSM 动画则优先反解 |
| 3 | 模型路线 | 先自回归 Transformer 或轻量扩散做基线；pybullet 仅用于评估/物理校验 |
| 4 | 旋转表征 | 6D 连续旋转表征（避免欧拉角万向锁） |
| 5 | 帧率 | 30 fps（YSM 动画常用 20–30） |
| 6 | 条件输入 | 动作类别 one-hot（后续可扩展为文本 / 轨迹） |

## 明确的非目标

- 不做模型渲染 / 材质 / 几何生成 —— 只产出**骨骼运动**
- 不改 YSM 模组源码 —— 只产出动画数据文件
