# 06 上游状态机与渲染机制（读 OpenYSM 源码所得）

> 2026-10-04。上游：`Desktop/YSM/YSM-Liaison`（OpenYSM 2.6.5.3，Fabric / MC 1.21.4）。
> 本篇回答"模型在不同状态下怎么渲染"：常态、动作、额外渲染分别由什么东西驱动。
> 配套：本篇是**运行时机制**，格式细节见 `05-模型格式调研.md`。

---

## 0. 一句话总览

一个 YSM 模型被渲染出来，要走 4 层：

```
① 资源 bundle    ysm.json → models/ animations/ animation_controllers/ functions/ textures/
② 控制器管线      PlayerAnimationController 注册 ~16 层「动画控制器」，按固定顺序执行
③ 图层/supplement hold / swing / use / armor / parallel 各层叠加到同一套骨骼上
④ 渲染层 Renderer  模型 mesh + 手持物 + 盔甲 + 鞘翅 + 鹦鹉；另有投射物/载具独立模型
```

**没有任何一层是"把所有骨骼一起画出来就行"** —— 每层只写它关心的那几根骨骼，
最后按层序合成。这就是上一版文档 §3b 里"不是所有骨骼同时渲染"的实现机制。

## 1. 控制器管线（`PlayerAnimationController`）

源码：`common/.../geckolib3/core/controller/controllers/PlayerAnimationController.java` L38-67

按**注册顺序**执行（顺序即合成顺序，后写的覆盖先写的同名骨骼）：

| # | 控制器 key | 判定器 | 过渡 tick | 作用 |
|---|---|---|---|---|
| 1 | `player.pre_parallel` | 动画链接 / Stop | 0 | **显隐归零**：先把可切换件收起来 |
| 2 | `player.parcool` | Parcool mod（可选） | – | 跑酷动作（有则抢占） |
| 3 | `player.vehicle` | `LivingMovementAnimationPredicate` | 0.1 | 骑乘时的移动适配 |
| 4 | `player.pre_main` | Stop（槽位） | 0 | 预留给用户覆盖 |
| 5 | **`player.main`** | **`AnimationManager`** | **0.1** | **常态/位移动作，见 §2** |
| 6 | `player.post_main` | Stop（槽位） | 0 | **常态变体**（idle 轮盘，见 §4） |
| 7 | `player.pre_hold` / `post_hold` | Stop（槽位） | 0 | 手持姿势前后钩子 |
| 8 | `player.hold_offhand` / `hold_mainhand` | OffHand/MainHandHoldPredicate | 0.1 | 按武器类型摆持握姿势 |
| 9 | `player.fire` | ItemUseAnimationPredicate（TAC 枪械） | 0 | 开枪 |
| 10 | `player.pre_swing` / `swing` / `post_swing` | ItemHoldAnimationPredicate | 0 | 挥击/攻击 |
| 11 | `player.pre_use` / `use` / `post_use` | InteractionHandAnimationPredicate | 0.1 | 使用（吃/喝/拉弓） |
| 12 | `player.passenger` | OffhandAttackAnimationPredicate | 0.1 | 副手攻击 |
| 13 | `player.carry_on` | CarryOn mod（可选） | – | 抱起方块/生物/玩家 |
| 14 | `player.cap` | PlayerBaseAnimationPredicate | 0 | 模型切换时的过渡动画 |
| 15 | `player.gui_hover` / `gui_focus` | 仅 GUI 预览（`IPreviewAnimatable`） | 0 | GUI 里的悬停/聚焦 |
| 16 | **`player.parallel`** | 动画链接 / Stop | 0 | **额外渲染叠加，见 §3** |
| 17 | `player.armor` | ArmorPredicate × 4 装备槽 | 0 | 穿上盔甲时的骨骼形变 |

注册方式有三种 processor：

- `ModelProcessor` —— 一次性固定控制器
- `ControllerSlotBinder` —— 槽位，模型可以自己用同名 key 覆盖（`pre_main/post_*`）
- **`ParallelProcessor`** —— 动态槽位，见 §3
- `ArmorSlotProcessor` —— 每个 `EquipmentSlot` 生成一份

## 2. 常态 / 位移位移动作（`player.main`）

源码：`common/.../client/animation/AnimationRegister.java` L16-44

**不是状态机**，是一个**按优先级自上而下第一个命中即用**的列表。
`Priority`: `HIGHEST=0 > HIGH=1 > NORMAL=2 > LOW=3 > LOWEST=4`。
常量 `MIN_SPEED = 0.05f`（limbSwingAmount 阈值）。

| 优先级 | 动画名 | 触发条件 | 循环 |
|---|---|---|---|
| HIGHEST | `death` | `isDeadOrDying()` | PLAY_ONCE |
| HIGHEST | `riptide` | `isAutoSpinAttack()`（三叉戟旋冲） | LOOP |
| HIGHEST | `sleep` | `Pose.SLEEPING` | LOOP |
| HIGHEST | `swim` | `isSwimming()` | LOOP |
| HIGHEST | `climb` | `Pose.SWIMMING` && 摆臂 > MIN_SPEED | LOOP |
| HIGHEST | `climbing` | `Pose.SWIMMING`（在梯子上不动） | LOOP |
| HIGHEST | `ladder_up` | `onClimbable()` && vy > 0 | LOOP |
| HIGHEST | `ladder_stillness` | `onClimbable()` && vy == 0 | LOOP |
| HIGHEST | `ladder_down` | `onClimbable()` && vy < 0 | LOOP |
| HIGH | `fly` | 创造飞行（远程玩家用 `PositionTracker`） | LOOP |
| HIGH | `elytra_fly` | `Pose.FALL_FLYING && isFallFlying()` | LOOP |
| NORMAL | `swim_stand` | 在水中 && 不落地 | LOOP |
| NORMAL | `attacked` | `hurtTime > 0` | PLAY_ONCE |
| NORMAL | `jump` | 不落地 && 不在水中 | LOOP |
| NORMAL | `sneak` | 落地 && 蹲 && 摆臂 > MIN_SPEED | LOOP |
| NORMAL | `sneaking` | 落地 && 蹲 | LOOP |
| LOW | `run` | 落地 && sprinting | LOOP |
| LOW | `walk` | 落地 && 摆臂 > MIN_SPEED | LOOP |
| **LOWEST** | **`idle`** | **恒 true —— 常态兜底** | LOOP |

（`fly` 会先看 `cap.isLocalPlayerModel()`：不是自己就用 `PositionTracker.isFlying()`，
因为远处玩家的 `abilities.flying` 客户端拿不到。）

`AnimationManager` 命中前还会先排除三种情况（`AnimationManager.java` L36-52）：
player 为 null、对象是 GUI 预览（`IPreviewAnimatable`）、玩家在 Parcool 中、玩家在载具上。
例外：Create mod 的机械装置 → 走 `parcool:ride_zipline`。

> ✔ **这张表就是训练数据分桶的天然标签**：一个模型的行为样本天然属于
> idle / walk / run / jump / sneak / swim / climb / fly / death / sleep / attacked 等互斥类。

## 3. 额外渲染（`pre_parallel` / `parallel`）

### 3.1 槽位是怎么发现的

`client/model/processor/ParallelProcessor.java` L32-45 —— 三条发现规则：

| 来源 | 匹配正则 | 例子 |
|---|---|---|
| 动画里的 animation entry | `^player\.(pre_)?parallel_.+$` | `player.parallel_0` |
| **functions/ 里的 molang 事件** | `^player_ctrl_(pre_)?parallel_.+$`（`_ctrl_` → `.`） | `@player_ctrl_parallel_7.molang` → `player.parallel_7` |
| 名为 `parallel[0-7]` 的动画 | `^parallel[0-7]$` | 自动挂到 `player.parallel_<n>` |

**结论：`functions/@player_ctrl_parallel_N.molang` 这个文件本身就是"申请一条额外渲染槽位"。**
这就是苦力怕狐里那 10 个 molang 文件的含义（我们包里只有 functions 没有对应的
`parallel.animation_controllers.json`，所以 default 行为由内置默认控制器补）。

### 3.2 内置默认（`builtin/misc/4_default_controllers/controller/main_controllers.json`）

```
player.pre_parallel_0  default → ["Hair_Physics", "pre_parallel1" ... "pre_parallel7"]
player.parallel_0      default → ["parallel0" ... "parallel7"]
player.hold_offhand    18 个 states（sword / bow / crossbow / shield / spear / axe / mace / potion ...）
player.post_swing      8 个 states（attack1..3 / attack_jump / fishing ...）
player.post_hold       15 个 states
```

注意 `pre_parallel_0` 的动画列表里**没有 `pre_parallel0`**，只有 `pre_parallel1..7`
（外加一个 `Hair_Physics`，头发物理属于这类"每帧无条件叠加"的层）。
索引 0 是"总槽"，1..7 是被它串起来的子动画。但由此也引出一条**待确认**的东西：
苦力怕狐的 `main.animation.json` 里有 `pre_parallel0..7` 共 8 段，而内置默认只播 1..7，
`pre_parallel0`（藏 `MooncakleH` 月饼头饰）在默认链路里**没有被引用** ——
要么由某个我们还没读到的数据驱动（例如 GUI 皮肤/节日开关），要么就是作者留下的死段。
做训练样本时建议把 `pre_parallel*` 这类"归零层"整体跳过（它们决定"不画什么"，
而 `or we have 477 个 cube` 的完整几何，不需要这层显隐归零。

### 3.3 本模型实例

`苦力怕狐/controller/wine_fox.animation_controllers.json` 自己声明了 3 个控制器：

| 控制器 | states | 语义 |
|---|---|---|
| `player.post_main` | `default` / `idle1..4` | **常态内的随机变体**。`default` 播 `new_idle_empty`；`v.next_idle==N && ctrl.idle && !ctrl.playing_extra_animation` 时切到 `new_idle_N`，播完或被 extra 打断就回 `default`。`blend_transition: 0.2` |
| `player.parallel_7` | `default` | **额外渲染**：`{"关兜帽": "v.hat==1"}, {"开兜帽": "v.hat==0"}` —— 二选一的条件动画列表 |
| `player.post_swing` | `default` / `挥舞斧头` / `放下斧头` / `方块挥舞` / `方块挥舞（跑）` | 由 `ysm.mouse(0)` 与持物状态驱动 |

`v.hat` 从哪来？`ysm.json` → `properties.extra_animation_buttons`：

```json
{"id": "开关兜帽", "name": "服装配置",
 "config_forms": [{"type":"checkbox","title":"是否脱帽","value":"v.hat"}]}
```

→ **玩家在 GUI 勾选"是否脱帽" → 写 `v.hat` → `player.parallel_7` 二选一 → `scale=0` 隐藏另一套**。
这正是 05 篇 §3b 里"20 根骨骼被 scale=0 隐藏"的开关来源。闭环了。

### 3.4 molang 可以直接抢跨 createslot

`functions/@player_ctrl_parallel_7.molang`：

```
ctrl.hold('offhand','$minecraft:flint_and_steel') && ctrl.hold('mainhand','$minecraft:tnt') ? {
    ctrl.set_animation('molang&arm:carry_block:main:tnt_start');
    return ctrl.state_continue; };
```

`functions/@player_ctrl_main.molang` 更狠 —— 它能在 `main` 层里抢判定：
抱着方块跑 / 抱方块跳 / 随机挑一个睡姿（`molang&sleep1..5`）/ extra 轮盘
（`(v.extra==11)` → `molang&extra:dooble`、`(v.extra==12)` → `sanfenmaiba`）。

`return ctrl.state_bypass` = 放弃接管，交还给内置判定链。

### 3.5 `ctrl.*` molang API 速查（`client/animation/molang/CtrlBinding.java` L43-89）

- **状态谓词**（和 §2 同表同优先级，且只有当该动画是当前选中项时才为真，
  靠 `positionTracker.getCachedModelId()` 比对）：
  `death riptide sleep swim climb climbing ladder_up ladder_stillness ladder_down fly
   elytra_fly swim_stand attacked jump sneak sneaking run walk idle`
- 其它谓词：`ctrl.playing_extra_animation`
- 函数：`ctrl.hold(slot,itemTag)`、`ctrl.swing(slot,itemTag)`、`ctrl.use(slot,itemTag)`、
  `ctrl.armor(...)`、`ctrl.ride(...)`、`ctrl.set_animation(name)`、
  `ctrl.set_beginning_transition_length(x)`、`ctrl.reset()`、`ctrl.indicate_reload()`
- 返回码常量：`state_continue=2`、`state_stop=3`、`state_pause=4`、`state_bypass=5`
- 循环类型常量：`loop=10`、`play_once=11`、`hold_on_last_frame=12`

各 mod 还会往这里挂东西：CarryOn / TAC / SWEM / Parcool / SlashBlade / SBackpack /
Create / BetterCombat / ImmersiveMelodies / Iron's Spellbooks。

## 4. 状态机 JSON 语法（`animation_controllers`）

Bedrock 控制器格式，YSM 支持的关键字段：

```jsonc
"player.<slot>": {
  "states": {
    "<state>": {
      "animations": ["名字"] | [{"名字": "<molang 条件>"}],   // 条件动画列表
      "transitions": [{"<目标state>": "<molang 条件>"}],      // 按序判定转移
      "blend_transition": 0.2 | {"0.0":1, "0.0167":0.965, ...},  // 秒→权重曲线
      "blend_via_shortest_path": true,                          // 角度最短路径插值
      "on_entry" / "on_exit": ["v.x = 0;"],                     // 副作用
    }
  }
}
```

- `q.all_animations_finished` 是常用的"播完就回去"条件
- `blend_transition` 可以是常数也可以是 9~10 个采样点的缓动曲线（上游默认用 smoothstep）
- `blend_via_shortest_path` 对欧拉角至关重要（防止 350°→10° 绕一圈）

## 5. 渲染层的"额外渲染"

源码：`client/renderer/layer/`、`client/renderer/`

| Layer | 干什么 |
|---|---|
| `CustomPlayerItemInHandLayer` | **只在 `model.rightHandBones()/leftHandBones()` 非空时**渲染手持物，用 `RenderUtils.prepMatrixForLocator` 把物品对齐到挂点骨骼；集成 SlashBlade / TAC / SWarfare |
| `CustomPlayerArmorLayer` | 盔甲 |
| `CustomPlayerElytraLayer` | 鞘翅 |
| `CustomPlayerParrotLayer` | 肩上鹦鹉 |

**挂点（`geckolib3/geo/render/built/GeoModel.java` L189-221）是一张固定表**，`strArr[0..34]`：

```
0 leftHand   1 rightHand   2 elytra   3 tacPistol   4 tacRifle
5 leftWaist  6 rightWaist  7 leftShoulder  8 rightShoulder
9 blade      10 sheath     11 head     12 backpack
13-19  extraLeftHandGroups  (7 组)
20-26  extraRightHandGroups (7 组)
27-34  passengerGroups      (8 组)
```

外加三个开关：`hasCustomLeftHand` / `hasCustomRightHand` / `hasCustomLimbs`（后者 = 有幕布背景）。
→ 苦力怕狐里的 `LeftHandLocator` / `RightHandLocator` / `ElytraLocator` 就是给这张表用的。

**投射物 / 载具是另一套完整模型**（`ysm.json` 里声明）：

```json
"projectiles": [ {"model":"models/arrow.json",  "match":["minecraft:arrow"]},
                 {"model":"models/trident.json","match":["minecraft:trident"]} ],
"vehicles":    [ {"model":"models/foxcar.json", "match":["minecraft:horse"|"mule"]} ]
```

→ 箭矢、三叉戟、坐骑（狐狸车）**不是主模型的一部分**，是独立的 model+animation+texture，
由 `ProjectileAnimationController` / `VehicleAnimationController` 驱动，
这两个控制器也各自注册 `pre_parallel` / `parallel`。

### 其它和渲染有关的 `ysm.json` 属性

```json
"preview_animation": "gui",        // GUI 预览播 gui 动画
"disable_preview_rotation": true,
"height_scale": 0.7, "width_scale": 0.7,   // ★ 游戏内整体缩放
"render_layers_first": false,      // 手持物先于/后于模型入队
"all_cutout": false,               // 全贴图走 cutout 而非 translucent
"gui_no_lighting": false,
"extra_animation": {"extra0":"变身", ... "开关兜帽(按钮)":"#开关兜帽", "月饼":"中秋快乐"}
```

⚠️ **`height_scale/width_scale = 0.7`**：上游渲染时模型整体再乘 0.7。
我们的离线渲染器是按 bbox 归一化到 1.8 m 的，两条路径要二选一，别混。

## 7. 对训练管线的推论

1. **状态桶已经有了现成答案**：直接复用 `AnimationRegister` 的 19 项 + `Priority`，
   把每段 Sample 打上 `state` 标签（idle/walk/run/jump/sneak/swim/climb/fly/death/sleep…）。
   它们互斥、有明确优先级顺序、OHLC 覆盖所有 playing 情形。
2. **同一帧的最终姿态 = 多层合成**：`main`( base ) + `hold`(武器姿) + `swing`/`use` + `parallel`(条件件) +
   `armor`。训练时如果只想学身体运动，取 **`main` 层就够了**；
   要学"拿着 Oswald 做 X"就必须保留 `hold`/`swing` 层并做层间优先级合并。
3. **额外件不要用"有没有画出来"来决定**，要用 `parallel` 槽位的条件（`v.hat`）当作**二值条件输入**，
   或者直接把两套几何都当作永远存在 —— 取决于模型要不要支持切换。
4. **吐出 glTF / npz 时的挂点**要保留表 `GeoModel` 那 35 组里的非空项，否则导出到别的引擎时
   手持物/鞘翅会掉到地上。
5. **`blend_transition` 曲线（smoothstep）和 `blend_via_shortest_path`** 必须实现，
   否则还原出来的 transition 段在 dataset 里会有跳变尖峰。
