## 1. 原来为什么一启动就崩（两个连锁原因）

### 1.1 `numpy.f2py` / `unittest` 被 spec 的 `excludes` 排除

原始报错（试跑 `--smoke` 时）：

```
ModuleNotFoundError: No module named 'numpy.f2py'
  run_pet.py:103 <module> → run_pet.py:68 main → pet\modelsource.py:238 load_source
  → ysm\ysmmodel.py:35 <module> → scipy\spatial\__init__.py:111
  → scipy\spatial\_kdtree.py:7 → scipy/spatial/_ckdtree.pyx:11 init scipy.spatial._ckdtree
  → scipy\sparse\__init__.py:251 → … → scipy\_lib\_array_api.py:24
  → scipy\_external\array_api_compat\numpy\__init__.py:9
  → scipy\_external\array_api_compat\_internal.py:64 clone_module
  → numpy\__init__.py:748 __getattr__
```

机制：`clone_module` 会遍历 `dir(numpy)` 并对每个名字做 `getattr`；而
`numpy.__getattr__` 对 `f2py` / `testing` 这类惰性属性**会真的去 import**。
只要那个子模块不在包里，整个 `scipy.spatial → scipy.sparse` 导入链就断。

修复过程中实测踩出来的**依赖顺序**（每一步都是下一步的前提）：

| 步骤 | 现象 | 处置 |
| --- | --- | --- |
| 1 | `No module named 'numpy.f2py'` | 把 numpy 2.4.6 的**真 f2py**（234 个文件）拷进 `_internal\numpy\f2py` |
| 2 | `ModuleNotFoundError: No module named 'fileinput'`（`numpy\f2py\crackfortran.py:141`） | 说明用「拷贝整套源码」会不断缺依赖；且 2.4.6 的 f2py 配 2.5.3 的 numpy 属于版本错配 |
| 3 | 换成**空壳桩** `numpy\f2py\__init__.py` | 通过 ✓ |
| 4 | `ModuleNotFoundError: No module named 'unittest'`（`numpy\testing\__init__.py:8`） | 拷 Python 3.12 的 `unittest`（13 个文件）进 `_internal\unittest` ✓ |
| 5 | `FileNotFoundError: '...\dist\YSM-Motion\configs\joints9.yaml'` | 见 1.2 |

> 结论：**spec 里的 `excludes` 是这次事故的根因**（`unittest`、`numpy.f2py` 都在里面），
> 不是 numpy/scipy 本身的问题。

### 1.2 `configs/` `models/` 不在 exe 能找到的路径上

```
FileNotFoundError: [Errno 2] No such file or directory:
  'C:\private\YSM-Motion\dist\YSM-Motion\configs\joints9.yaml'
  pet\loader.py:79 load_hide_bones
```

机制：源码里每个模块都是

```python
ROOT = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
DLL  = os.path.join(ROOT, "native", "raster.dll")
```

源码运行时 `ROOT` = 仓库根。冻结后 `__file__` = `<_MEIPASS>\pet\loader.pyc`
（onedir 模式下 `_MEIPASS` 就是 `_internal\`），三连 dirname 得到的 `ROOT`
是 **exe 所在目录** `dist\YSM-Motion\`；而 `COLLECT` 只会把 `datas` 放进
`_internal\`。两边对不上 → 资源找不到。

`:755` 都用它算 `computeViewMatrixFromYawPitchRoll` / `computeProjectionMatrixFOV`

PyPI 上 pybullet 没有 Windows 轮子（`pip install pybullet` 会去编译 C++），
conda-forge 有；`requirements.txt` 原本也写着「pybullet==3.2.5 conda-forge 手动安装」。
源码方式实测（Anaconda 3.14.6 强跑 `--smoke`）：模型能正常加载、解析、解密，

**已解决（2026-10-05 19:00）**，装的就是 conda-forge 的预编译包：

```
conda install -y --override-channels -c conda-forge --freeze-installed pybullet
```

装上 `pybullet-3.25-py314hcfc7f4e_5` + `bullet-cpp-3.25-hd8fd7ce_5`（共 85.4 MB）。

- ⚠️ **别用裸的 `conda install -c conda-forge pybullet`**：本机 conda 配了 7 个 channel
  （含清华镜像），解算会卡死——实测跑了 30 分钟、CPU 满载还停在 `Solving environment`。
  加 `--override-channels -c conda-forge` 把 channel 缩到一个，2 分钟就装完。
- 副作用：`conda`(26.5.3→26.7.3)、`certifi`、`openssl`、`ca-certificates` 被换成
