# 02 数据规格

在数据管线动工前先把格式钉死。所有后续模块以本文为准。

## 1. 目录约定

| 目录 | 内容 | 是否进 git |
|---|---|---|
| `data/raw/` | 原始数据（动捕文件、YSM 模型/动画样本）。**只读** | ❌ |
| `data/interim/` | 已重定向到统一骨架、但未归一化的序列 | ❌ |
| `data/processed/` | 归一化后的张量 + 元数据，可直接喂模型 | ❌ |
| `configs/skeleton.yaml` | 骨架定义（关节名、父关节、T-pose） | ✅ |
| `configs/skeleton_map.yaml` | 源骨架 ↔ 目标 YSM 骨骼映射表 | ✅ |

## 2. 骨架定义（`configs/skeleton.yaml`）

```yaml
name: ysm_humanoid_v0
fps: 30
joint_names: [hips, spine, chest, neck, head, ...]   # 顺序即索引
parents:      [-1, 0, 1, 2, 3, ...]                  # -1 = 根关节
tpose_offsets: [[0,0,0], ...]                        # 每个关节在 T-pose 下相对父关节的偏移
```

- `joint_names` 一经确定就是全局索引，**不允许随便增删**（会作废所有已处理数据）
- 改骨架 = 换 `name`，旧 `name` 的 processed 数据全部重跑

## 3. 序列张量格式

单条样本存为一个字典，序列化为 `npz`：

| 字段 | 形状 | 说明 |
|---|---|---|
| `root_vel` | `[T, 3]` | 根节点水平速度 + 朝向角速度（前 2 维为平面速度，第 3 维为 yaw 角速度） |
| `root_height` | `[T, 1]` | 根节点离地高度 |
| `local_rot` | `[T, J, 6]` | 各关节**相对父关节**的旋转，6D 连续表征 |
| `foot_contact` | `[T, 4]` | 左右脚跟/脚尖接触标签（0/1），可由 pybullet 或速度阈值生成 |
| `meta` | — | 动作类别、帧率、来源文件、骨架名 |

### 为什么用 6D 旋转表征

- 欧拉角：万向锁 + 角度回绕（359° 和 1° 距离被算成 358°）
- 四元数：双覆盖（q 与 -q 同姿态），回归目标不唯一
- **6D（旋转矩阵前两列）**：连续、无奇异、唯一，回归友好；取用时再做 Gram-Schmidt 还原矩阵

### 为什么存"局部旋转"而非全局

局部旋转（相对父关节）天然与骨架绑定、与根位移解耦，
换根运动（比如让人边走边转向）时不需要重算整棵树。

## 4. 归一化

- 对 `root_vel` / `root_height` / `local_rot` 各自按训练集算均值与标准差
- 统计量存 `data/processed/stats.npz`，**导出反算时必须用同一份**
- `foot_contact` 不归一化

## 5. 重定向（源骨架 → 目标骨架）

1. **关节名映射**：查 `configs/skeleton_map.yaml`，缺失关节标记为 `unmapped`
2. **坐标系对齐**：源/目标骨架的关节静止朝向可能不同（Y 轴朝上 vs Z 轴朝上），
   需要为每个关节存一个"静止姿态修正四元数"
3. **骨骼长度缩放**：源骨架与目标骨架比例不同，按 T-pose 骨长比例缩放根位移与偏移
4. **验证**：重定向后跑 FK，检查骨骼长度恒定、无爆炸姿态

> 重定向是最容易静默出错的环节 —— 必须靠 `tests/` 里的 FK 与骨长断言兜底，
> 而不是靠肉眼看动画。

## 6. 数据质量门槛

处理完每条序列后跑这些检查，不通过就丢弃并记录：

- 无 `NaN` / `Inf`
- 相邻帧关节角速度不超过阈值（剔除抖动/跳变样本）
- 骨骼长度在整条序列内保持恒定（误差 < 1%）
- 脚部不长时间穿地（`root_height` 与足部 FK 高度自洽）

## 7. 最小可用数据量

CPU 训练的现实约束下，先按这个规模验证管线跑通：

- 动作类别：4（idle / walk / run / jump）
- 每类 200–500 条，序列长度 60–120 帧
- 总量控制在几 GB 以内
